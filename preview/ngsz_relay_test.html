カゴ落ちReCV直接連携(ngszRelay)の再現ページ

テストモード(URLパラメータ):
・パラメータ無し … フラグOFF(既定)。ReCVスタブは読み込むが、 チャットを完走しても sendPhone / sendMail が一度も呼ばれないことを確認する
・?relay=1 … ngszRelay: true。ご連絡先(メール+電話)の「次へ」で sendMail・sendPhone が正規化済みの値で各1回呼ばれる
・?relay=1 のまま✎修正 … 回答バブルの✎でご連絡先を出し直し、 同じ値のまま確定 → 再送されない / 値を変えて確定 → 新しい値で再送される(呼び出し回数で判定)
・?relay=1&nostub=1 … ReCVタグが無いページ(window.ngszV2 が存在しない)。 エラーにならずチャットは最後まで完走し、2秒×5回のリトライ枯渇で dataLayer に hs_chat_lead_relay_miss が1回だけ出る(約10秒後)
・?relay=1&late=1 … ReCVタグを3秒遅延で注入(?late=12 のように秒数指定も可)。 リトライで拾って送信されること
  ↳ ⚠️この遅延は「ページ読込」からの秒数。手で操作するとご連絡先の確定はどうしても遅延より後になり、 最初の呼び出しで即成功してしまう(=リトライ経路を通らない)。リトライ経路そのものを確認したい時は ?relay=1&nostub=1 でご連絡先を確定させ、 右下パネルの「今すぐReCVタグを注入する」を10秒以内に押す(2秒×5回のリトライが拾って送信する)

右下の黒いパネルにスタブの呼び出しログと dataLayer の relay 系イベントが出る。 コンソールで window.__ngszCalls(呼び出し配列)・window.dataLayer でも同じ内容を確認できる。
※このページのシナリオは standard、質問を短くするため skip: { password, sex } を入れてある(メール・電話は必ず質問する)。
チェックリスト
① パラメータ無し … 完走しても呼び出し 0 件(既定OFFの確認)
② ?relay=1 … sendMail=1回 / sendPhone=1回、値がチャットの入力どおり(電話はハイフン除去済み)
③ ?relay=1 + ✎で同値確定 … 呼び出し回数が増えない
④ ?relay=1 + ✎で値変更 … 変えた項目だけ新値で+1回
⑤ ?relay=1&nostub=1 … チャットが最後まで進む/hs_chat_lead_relay_miss が1回だけ
⑥ ?relay=1&nostub=1 でご連絡先を確定 → 10秒以内に「今すぐReCVタグを注入する」を押す … リトライが拾って送信され、miss は出ない
⑦ どのモードでも、送信された値は電話とメールだけ(氏名・住所・パスワード・カードが渡っていない)
